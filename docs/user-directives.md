# 用户明确交代过的事项（硬约束）

> 这份文件与 `docs/lessons-and-shortcuts.md` 分工不同：
> 那边记**技术坑**（工具/API/构建会怎么咬人）；这里记**用户要求**（他明确说过"要这样""不要那样"）。
> **技术坑可以试错，这里每一条都是硬约束**——违反过的基本都付了代价，见最后一列。
>
> 来源：用户级长期记忆、33 份工作日志里的"用户原话/要求/纠正"、以及 2026-10-19 会话中的要求。
> 若与其它文档冲突，**以本文件为准**（因为这里代表用户本人）。

---

## A. 交付与验证

| # | 要求 | 具体做法 | 违反过的代价 |
|---|---|---|---|
| A1 | **独立验证用户自述的完成状态** | 用户说"我自己来""已经关了""都重启了""已经打开了工程"——**必须自己查一遍**（进程、文件、日志、API），不能据此推进 | 实测连接器仍跑旧引擎；实测他的 TIA 里并没有工程 |
| A2 | **验证深度必须如实说明** | 只做了"构建+闸门+读实现"就说这一级；**不许暗示做过真机验证** | 曾用"已修复"口径描述未经真机验证的改动 |
| A3 | **摘要/文档必须与磁盘实际交付一致** | 说改了 8 处就是 8 处；清单里有的文件必须真在 | 对"摘要漂移"高度敏感，多次被驳回 |
| A4 | **结论要有权威依据** | 判工程行为看**权威配置块 + IO 映射块**（FunctionInit/IOMapping），不是"对象存在就算" | — |
| A5 | **先跑通基础功能再叠加** | 现有工程先验基础链路；新项目先总结现有模板作基线 | 返工成本高 |
| A6 | **给链接或预览，不要只给路径** | 交付物直接给可点开的链接/预览，别只描述"在 xx 目录" | — |

## B. 安全（这几条代价最大）

| # | 要求 | 具体做法 | 违反过的代价 |
|---|---|---|---|
| B1 | **绝不关掉用户正在用的 TIA** | 杀进程只按"我启动的进程树"；引擎 PID 未知就什么都不杀；**对 `Attach()` 得到的门户永不 Dispose** | **两次造成未保存改动丢失** |
| B2 | **密钥不外泄** | 桌面 `APIkey.json` 含 PAT 等，**禁止回显/写进仓库/写进日志** | — |
| B3 | **已授权连接默认只读** | 飞书 / 腾讯文档 / 钉钉等，**授权 ≠ 可自行改动**；写操作逐次征得明确同意 | 用户明确立过这条铁律 |
| B4 | **加密块先问密码，不做字典/撞库** | know-how 保护块挡住工作时**停下来问密码**；**不为此新增 MCP 工具** | 用户明确要求过 |
| B5 | **破坏性操作先警告、列清单、等确认** | 个人目录禁 `rm -rf`；删文件走回收站/`send2trash` | — |

## C. 流程与节奏

| # | 要求 | 具体做法 |
|---|---|---|
| C1 | **先给计划再执行，标注风险等级** | 任务分解 + 复杂度/风险标注；但**指令清晰时直接干**，不要"分析完再问要不要继续" |
| C2 | **跑偏了先纠正范围再继续** | 发现理解偏了立刻停下说明并重定范围 |
| C3 | **迭代工作流** | 专家规划 → 增量构建并验证 → 交付；每步"写→验→报" |
| C4 | **同一问题连修 3 次不成就停手** | 说明已试过什么，请求协助；不许无限打补丁 |
| C5 | **不要让用户反复提醒同一件事** | 用户原话："就不能自己在程序中读取？如果使用过程中还得我每次提醒" ⇒ 能自动化就自动化，别让他当人肉开关 |
| C6 | **简短的确认就是确认** | "你开始吧 / 继续 / 查吧 / 推送吧"= 按当前方案执行；不要重复问已经答过的问题 |

## D. 文档与表达

| # | 要求 | 具体做法 | 违反过的代价 |
|---|---|---|---|
| D1 | **仓库去 AI 化** | README/CHANGELOG 不许 AI 腔：禁 `⚡`、"免费开源…不含授权校验"这类自辩、"几分钟内"这类浮夸；"痛点→常见问题""笨 AI→弱模型"；**提交署名必须是 `1748477582`** | 2026-08-17 专门重写过一次历史 |
| D2 | **正式书面语，不口语化也不用管理黑话** | 禁"从 0 到 1 / 闭环 / 赋能 / 沉淀 / 显著提升"；也禁"做了两类设备的活"这种大白话；**允许用行业术语压缩篇幅** |
| D3 | **正式工作记录只写有分量的事** | 不写文档整理、参数微调、协助性调试；**不含时间概念**（周数/近期/入职后）；**不提 AI 工具** |
| D4 | **中文环境用简体中文** | 港/澳/台表述按官方口径（中国香港/中国台湾/中国澳门） |

> ⚠️ **D1 的实际状态（2026-10-19 自查）**：`CHANGELOG.md` 与两份 `README` 目前是干净的中文、无 AI 腔关键词；
> 但**当天的 4 条提交信息是英文、且带第一人称过程叙述**（"I claimed six times…"），属于边缘违反。
> 如需彻底一致，可把这几条压成一条中文提交信息（重写历史，需单独确认）。

## E. 存储与平台（跨项目通用）

| # | 要求 | 具体做法 |
|---|---|---|
| E1 | **文件优先云端，减少本地** | 报告/表格/文档/PPT 优先飞书或腾讯文档；**代码/配置/脚本**这类类型不支持或需本地运行的可留本地 |
| E2 | **百度网盘「我的应用数据」** | 子目录 `/我的应用数据/AI产出文件/`；⚠️ 该连接器**不能传任意二进制**（只能文本/URL 转存），大文件须告知限制 |
| E3 | **交付形态偏好可交互/可编辑** | 时间轴视图、在线编辑、批注 > 只读静态 |

## F. 本仓库专属

| # | 要求 | 具体做法 |
|---|---|---|
| F1 | **每个版本都要在 `CHANGELOG.md` 记一条** | 按"新增/变更/修复/移除"四类；工具总数/分层变化必须写（用户问过"为什么不做版本更新记录"） |
| F2 | **改工具 = 同步三份** | 引擎 `tools/list` = `manifest/tools-list.json` = `docs/tool-capability-matrix.md`；**改描述也要** |
| F3 | **一份配置覆盖多版本；版本由用户决定，不许预设** | 用户原话："一个 MCP 覆盖多版本"＋"不需要你自己预先设定博图版本"。做法：**先探测本机装了哪些 → 让用户确认 → 让用户选**；非交互时**显式报错并列出选项**，绝不默默选最高。装完可随时用 `switch-version.ps1` 改 |
| F4 | **换机器/换 agent 必须能自行发现** | 用户原话："以前和以后加入的文件/代码/功能都要能被任何人找到并调用" ⇒ `AGENTS.md` + `docs/INDEX.md` + CI `content-index` |
| F5 | **不许谎报成功** | 静默失败 + 报成功比报错更糟（下载预检那次就是） |

## 交付前自查（逐条打勾，别跳）

1. [ ] 我有没有**据用户自述**推进？→ 独立验证过一遍（A1）
2. [ ] 我说的"已验证"是**哪一级**？→ 如实写清（A2）
3. [ ] 文档/清单/提交信息里写的数字与文件，**磁盘上真是这样**？（A3）
4. [ ] 有没有可能**碰到用户正在用的 TIA**？（B1）
5. [ ] 有没有**回显密钥**、或把 token 写进文件？（B2）
6. [ ] 对已授权的外部系统，我是不是**只读**？（B3）
7. [ ] 破坏性操作**警告 + 清单 + 确认**了吗？（B5）
8. [ ] 文风：**无 AI 腔、无管理黑话、无时间概念**？（D1–D3）
9. [ ] 改工具是否**同步三份 + 重生成索引**？（F2、F4）
10. [ ] `CHANGELOG.md` 记了吗？**行为变更**写清了吗？（F1）
